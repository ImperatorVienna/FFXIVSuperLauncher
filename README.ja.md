# FFXIV Super Launcher

## バージョン 2.2.0

Windows x64 と Linux x86_64 を同時リリースします。2.2.0 では Windows でのネイティブ起動とデスクトップショートカットに対応し、Dalamud 更新の復旧処理と中国版の QR ログインを改善しました。操作画面も改善しています。[2.2.0 リリースノート](docs/releases/2.2.0.ja.md)をご覧ください。

**Windows と Linux** に対応するコミュニティ製 FINAL FANTASY XIV（FFXIV）ランチャーです。**中国版、繁体字中国語版、グローバル版**クライアントに対応します。Windows ではネイティブに、Linux ではインストール済みの Proton を使ってゲームを起動します。

本プロジェクトは **[ImperatorVienna](https://github.com/ImperatorVienna)** が保守し、[XIVLauncher](https://github.com/goatcorp/FFXIVQuickLauncher)、[XIVLauncherCN](https://github.com/ottercorp/FFXIVQuickLauncher)、[XIVLauncherCN (Soil)](https://github.com/AtmoOmen/FFXIVQuickLauncher) のソースコードと知見を基に開発を継続しています。また、繁体字中国語版のログインプロトコルと機能設計では [XIVTCLauncher](https://github.com/cycleapple/XIVTCLauncher) を参考にしています。独立して保守されるコミュニティの派生プロジェクトであり、Square Enix、Shengqu Games、USERJOY の公式リリースではなく、上記の上流プロジェクトによる保守や推奨も受けていません。原作者の著作権表示とライセンス通知は保持しています。

> **対応プラットフォーム：Windows x64、Linux x86_64。** [Releases](https://github.com/ImperatorVienna/FFXIVSuperLauncher/releases)から Windows ZIP または Linux AppImage をダウンロードしてください。

内蔵ブラウザーは公式ページと Web 認証で共用し、各ゲームリージョンのログインモジュールから独立しています。

## 機能

- **3 つのゲームリージョン**：共通の画面からクライアント、認証情報、Dalamud、プラグインデータを個別に管理します。プラットフォーム別の処理で Windows のネイティブ起動または Linux/Proton 起動を行います。
- **Linux の Proton 対応**：システムと Steam ライブラリ内のインストール済みバージョンを検索し、手動パス指定にも対応します。CachyOS / proton-cachyos-slr 環境で実機検証済みです。
- **アカウント管理**：ゲームリージョンごとにアカウントを追加・選択・編集・削除できます。認証情報はローカルの平文ファイルに保存します。
- **認証コード**：繁体字中国語版とグローバル版で、認証コードの手動入力とローカルでの TOTP 自動生成に対応します。グローバル版では、アカウントで OTP を有効にしている場合のみ入力が必要です。
- **ゲーム更新**：対応するゲームリージョンのクライアントパッチを確認・インストールします。ゲームを起動せず、更新のみ行うこともできます。
- **Dalamud とプラグイン**：Dalamud は任意で有効にできます。ゲームに入らずにプラグインの有効・無効を管理し、Dalamud とプラグインの更新を確認できます。
- **ゲームリージョン間の同期**：「外部リポジトリを同期」「インストール済みプラグインを同期」「プラグイン設定を同期」で、同期元と同期先を選択して種類ごとに同期します。外部リポジトリの同期では一覧と有効状態のみを置き換え、同期先のメインリポジトリ、同梱リポジトリの有効設定、その他の Dalamud 設定を必ず保持します。元のデータはバックアップされます。
- **Steam 連携**：両プラットフォームでグローバル版（Steam 版）のアカウント認証に対応します。認証時は Steam を起動してください。Linux ではさらに Steam 互換ツール登録、Steam 起動時の全画面表示、Steam スクリーンキーボードを利用できます。Windows にはこれらの Linux 専用設定を表示しません。
- **画面とお知らせ**：Electron のグラフィカルインターフェースは简体中文、繁體中文、日本語、English に対応し、再起動せずに即座に切り替えられます。対応するゲームリージョンの公式イベントとお知らせを表示し、ゲーム公式サイト、サーバー状況などの公式ページへのリンクを提供します。
- **サードパーティーのプラグインリポジトリ**：プラグイン管理の右側で、リポジトリの追加、編集、有効化/無効化、削除、接続確認ができます。中国版のプラグイン更新では、有効な同梱リポジトリも認識します。
- **中国版のデータセンター間移動**：移動申請の送信、履歴の照会、元のデータセンターへの帰還に対応し、完了後にゲームを起動できます。 DCTravelerX（[Dalamud-DailyRoutines/DCTraveler](https://github.com/Dalamud-DailyRoutines/DCTraveler)）のゲーム内トラベルと認証復旧に対応します。
- **ストレージのクリーンアップ**：「このアプリについて」からダウンロードキャッシュ、ログ、内蔵ブラウザーのキャッシュを削除できます。起動時には失効を確認できたセッション記録を回収します。

サードパーティー製ランチャー、Dalamud、プラグインを使用する前に、ゲームの関連利用規約を読み、使用に伴うリスクをご自身で判断してください。Dalamud は既定で無効です。本プロジェクトはアカウントの安全性やプラグインの利用可能性を保証しません。

## 特長

- **2 種類の配布形式**：Windows x64 ZIP と Linux x86_64 AppImage。macOS、ARM、32 ビット x86 版は提供しません。Windows ではフォルダー全体を保持し、EXE だけをコピーしないでください。
- **Linux はインストール済みの Proton を使用**：ランチャー付属の Wine 環境は不要です。Windows はネイティブ起動のため Proton を必要としません。
- **各ゲームリージョンの一元管理**：1 つのランチャーで中国版、繁体字中国語版、グローバル版のログインを切り替え、アカウント、クライアント、プラグインのデータを個別に保存します。各ゲームリージョンの Dalamud 本体は必要に応じてダウンロードします。実行パッケージには共用または事前配置された補助コンポーネントが含まれる場合があります。
- **ゲーム外でのプラグイン管理**：ゲームに入らずにプラグインの有効・無効を変更し、更新するプラグインを選択し、ゲームリージョン間で設定を同期できます。
- **認証情報の管理**：ゲームリージョンごとにアカウントのログイン認証情報を管理し、ローカルの平文保存とローカル TOTP 生成に対応します。
- **グローバル版で Steam 版の既存 pfx を再利用**：公式ランチャーから FFXIV Super Launcher に切り替えた後も、元の pfx にあるローカルのゲーム設定とキャラクター設定ファイルを引き継げます（サーバーに保存されたキャラクターの進行状況には関係しません）。
- **繁体字中国語版の Dalamud 注入への対応**：Linux/Proton 環境向けに注入処理を調整し、グローバル版と同じ entrypoint 経路を使用して、元の繁体字中国語版の注入処理にあった ArgFixer をスキップします。キャラクターへのログイン、プラグインのインストールと実行を実機で検証済みです。
- **中国版の Dalamud ブランチ選択**：Dalamud-DailyRoutines ブランチと更新元を採用し、ottercorp ブランチのプラグインブラックリスト方針は引き継ぎません。これは、すべてのプラグインに互換性があることや、ゲームの利用規約の対象外であることを意味しません。

## インストールと初回利用

### 動作条件

- Windows x64 または x86_64 Linux のグラフィカルデスクトップと、ゲームに必要なドライバーおよび依存コンポーネント。
- Linux：インストール済みの Proton と対応する Steam Linux Runtime。
- 対応するゲームリージョンの完全なクライアント。**本プロジェクトには、空のフォルダーにゲームクライアント全体をダウンロードする機能はありません。**
- Linux：選択した Proton に必要な Vulkan サポート。

実行パッケージには .NET と Electron（Chromium と Node.js を含む）の実行コンポーネントを内蔵しており、.NET SDK、Electron、ブラウザーを別途インストールする必要はありません。他のディストリビューションの依存関係と検証状況は、各リリースノートを参照してください。CachyOS で動作することは、すべてのディストリビューションやサンドボックス環境でテスト済みであることを意味しません。

### Linux AppImage

[Releases](https://github.com/ImperatorVienna/FFXIVSuperLauncher/releases)から Linux AppImage をダウンロードし、実行権限を付与して書き込み可能なディレクトリから起動してください。

### Windows ZIP

`FFXIVSuperLauncher-2.2.0-win-x64.zip` を完全に展開し、`FFXIV Super Launcher` フォルダーを書き込み可能な場所に置いて `FFXIVSuperLauncher.exe` を起動してください。ZIP 内から直接実行したり、EXE だけを移動したりしないでください。.NET と Electron は同梱されています。

ランチャーは固定の起動スクリプトとアイコン付きデスクトップショートカットを更新します。移動や名前変更の後は EXE を直接一度起動してパスを更新してください。スタートメニューへの登録は行いません。Windows の初回設定では Steam / Proton のパス検索を省略します。Steam 認証には起動中の Steam が必要ですが、認証のためにインストールパスを入力する必要はありません。

### 共通の初回設定

初回設定ウィザードは English で始まり、ランチャーの表示言語、ゲームリージョンを順に設定し、Linux では Steam / Proton 環境も設定します。グローバル版では、クライアント言語、CDKey バージョン、EU アカウントのストア優先言語も設定できます。初期値は NA、英語クライアント、ストア優先言語は英語（英国）です。個々の選択は即座に保存され、初回設定の完了後にランチャー更新の自動確認を行います。

その後、「言語とリージョン」でクライアントのディレクトリを設定してください。`game` サブディレクトリを含むゲームのインストール先を選択します。グローバル版には、完全な `boot` サブディレクトリも必要です。

「ログイン認証情報の管理」の「アカウントを追加」で認証情報を入力し、「認証情報を保存」をクリックしてください。「ゲーム」ページに戻り、「ログイン名を選択」でアカウントを選択してから、「ログインして起動」をクリックします。中国版の新規アカウントはログイン名のみ入力し、初回ログイン時に QR コードを読み取ります。成功するとクイックログイン認証情報が自動保存されます。

### 表示言語とグローバル版の言語設定

「言語とリージョン」ページで設定します。

- **ランチャーの表示言語**：選択すると即座に保存され、すべてのページが切り替わります。ランチャーの再起動は不要です。
- **グローバル版クライアントの言語**：グローバル版を選択した場合のみ表示され、日本語、English、Français、Deutsch から選択できます。選択すると即座に保存され、次回のゲーム起動時に反映されます。ゲーム実行中は変更できず、他のゲームリージョンに切り替えても、この選択は消去されません。
- **アカウントの CDKey バージョン**：アカウントの実際のライセンスに合わせて JP、NA、EU を選択します。既定は NA です。対応する公式サイト、ストア、Mog Station、イベントとお知らせの取得元を選ぶ設定であり、アカウントのライセンスを変更するものではありません。
- **公式サイトとストアの優先言語**：CDKey バージョンが EU の場合のみ表示され、English(UK)、Français、Deutsch から選択できます。公式サイト、ストア、お知らせの言語を選ぶために使用します。これらの Web ページの設定は変更後に自動保存され、クライアント言語とは独立しています。

## Steam と Proton

### Steam ライセンスのアカウント

グローバル版アカウントの CDKey を Steam で購入した場合は、「CDKey は Steam で購入しました」を有効にし、ログイン前に Steam クライアントがサインイン済みで実行中であることを確認してください。

ランチャーは Steam アカウントのパスワードの入力や保存を要求しません（Steam は CDKey の所有権確認にのみ使用し、ゲームへのログインは引き続き Square Enix アカウントで行います）。

### Steam からランチャーを起動する — Linux

「Steam と Proton の設定」で「Steam 起動に対応」を有効にすると、**FFXIV Super Launcher** を Steam compatibility tool として登録できます。Steam を再起動し、Steam ライブラリの FFXIV のプロパティで、この compatibility tool を選択してください。チェックを外すと登録を解除できます。有効にすると、Steam から起動した際に自動で全画面表示となり、入力欄をクリックすると Steam の仮想キーボードの呼び出しを試みます。呼び出せない場合はキーボードでの入力を案内し、キーボードを開くためだけに Steam を起動することはありません。デスクトップのウィンドウサイズと最大化状態は別に保持します。

**Ctrl+Q** または **Alt+F4** でランチャーを正常終了できます。Esc はキャンセル可能なダイアログを閉じます。一部の Gamescope セッションでは `dxgi=n` のみが渡され、ゲームの直接起動時にグラフィックス DLL の実装が混在する場合があります。ランチャーは条件に応じて不足する D3D11 の読み込み設定を補い、ユーザーの明示的な設定は保持します。この問題の対策として追加した Steam 起動オプション `env WINEDLLOVERRIDES="dxgi,d3d11=n" %command%` は削除できます。それ以外の独自の起動オプションは残してください。

この機能は Steam からの起動入口を提供するもので、**Steam アカウント認証を有効にするものではありません**。アカウント認証は引き続き「CDKey は Steam で購入しました」で制御します。

この機能は固定の起動スクリプトを使用します。AppImage を手動で移動・改名した後は、一度起動すればパスが更新されます。ランチャーの自動更新後は、自動的に再起動してパスを更新するため、手動操作は不要です。

### 互換性環境 / pfx — Linux

既定では、「Steam と Proton の設定」の「Proton データディレクトリ（ここに pfx を自動作成します。専用ディレクトリを推奨）」を使用します。グローバル版では「グローバル版で Steam の既存 pfx を使用」を有効にして、インストール済み Steam 版 FFXIV の既存環境と、その中のローカルゲーム設定を再利用できます。

このオプションが無効の場合、グローバル版も他の 2 つのゲームリージョンと共通の環境設定を使用します。Steam の既存環境を選択しても、プラグイン設定の移行や同期は行いません。

## 更新方法

### Windows フォルダーの更新

更新確認とダウンロードは Linux と共通ですが、Windows 専用 ZIP と署名付き更新マニフェストを使用します。確認後、署名、ZIP のハッシュ、ファイル一覧を検証します。別の更新プロセスがランチャーの終了を待ち、プログラムファイルだけを置き換えて再起動します。アカウント、設定、プラグイン、ログは保持します。旧ファイルは `update-backups` に保存し、インストール失敗時は復元を試みます。更新前にゲームを終了してください。置き換えと復元の自動テストは合格していますが、Windows 実機でのオンライン更新から終了・再起動までの一連の動作は引き続き検証が必要です。

### Linux AppImage の更新

更新の自動確認は既定で有効で、初期設定完了後に安定版を確認し、以降も起動するたびに確認します。「このアプリについて」の「アプリケーションメニューに追加」の右側にある「更新を自動確認」を無効にできます。スイッチの状態にかかわらず、「このアプリについて」のバージョン番号の横にある「更新を確認」を使用できます。更新チャンネルの選択機能はありません。AppImage の更新はユーザーの確認後に行い、全体のダウンロードが完了するとマニフェストの署名と SHA256 を検証してから元のファイルを置き換えます。更新ファイルは元のディレクトリに新しいバージョン番号を含むファイル名で保存し、旧版は `.previous` として保持します。Steam とアプリケーションメニューは `<launcher directory>/appimage-launcher` を経由して起動します。AppImage を手動で移動・改名した後は、一度ダブルクリックして起動し、パスを自動更新してください。その後も Steam やアプリケーションメニューから起動できます。複数のコピーがある場合は、最後に起動したファイルを使用します。更新前にゲームを終了してください。インストール後は、アプリケーションメニューへの登録に依存せず、新しい AppImage の絶対パスを使って画面を自動的に開きます。アカウントと設定は独立して保存され、バックグラウンドの更新確認に失敗してもゲームへのログインを妨げません。

旧 AppImage を実行するとランチャーを以前のバージョンに戻せます。戻した後は更新の自動確認を無効にしてください。旧版でこのスイッチを利用できるかどうかは、そのバージョンによります。複数の AppImage が同じ起動入口を共用する場合は、最後に起動したファイルを使用します。

アプリケーションメニューの入口は AppImage の起動時に自動作成します。「このアプリについて」の「アプリケーションメニューに追加」は手動で入口を再作成するためのもので、通常は追加の操作は不要です。既定の入口ファイルは `~/.local/share/applications/xivlauncher-super.desktop` で、`XDG_DATA_HOME` に従います。AppImage を手動で移動・改名した後は、直接一度起動すれば記録が更新されます。

AppImage の起動時は、まず不足している既定の設定を作成し、固定の起動スクリプトとアプリケーションメニューの入口を書き込んでから、初期設定に進みます。更新の自動確認は初期設定完了後に行います。入口は「このアプリについて」から手動で再作成することもできます。設定完了後や入口の追加後は、利用可能なアプリケーションメニューのキャッシュをバックグラウンドで更新し、ターミナルウィンドウは開きません。キャッシュの更新に失敗してもランチャーは使用できます。メニューの入口は永続保存されたアイコンファイルの絶対パスを使用するため、AppImage のマウント解除後もアイコンを読み取れます。

### ゲーム、Dalamud、プラグインの更新

| 操作 | 動作 |
| --- | --- |
| ログインして起動 | アカウント認証成功後にゲーム更新を確認し、Dalamud が有効ならその更新も確認してからゲームを起動 |
| ゲームの更新を確認して適用 | 現在のゲームリージョンのクライアントのみ更新。中国版・繁体字中国語版は事前ログイン不要。グローバル版はアカウント認証が必要ですが、ゲームは起動しません |
| Dalamud の更新を確認して適用 | 現在のゲームリージョンの Dalamud を手動確認 |
| プラグインの更新を確認して適用 | プラグインに記録された配布元リポジトリで更新を確認し、ユーザーがインストール対象を選択 |

Dalamud 更新時の接続がタイムアウトした場合は、既存の使用可能なバージョンで起動を続行するか、Dalamud を無効にして起動できます。無効化は設定に保存されるため、後で手動で有効に戻す必要があります。既存バージョンがない、または互換性がない場合、更新をスキップしても起動できるとは限りません。

上記の Dalamud とプラグインの 2 つの更新ボタンは「Dalamud とプラグイン」ページにあります。プラグインのチェック状態を変更すると即座に保存され、次回のゲーム起動時に反映されます。「プラグインの有効状態を再読み込み」と「リポジトリの状態を再読み込み」は、それぞれ対応するデータを読み直し、各操作のメッセージを消去します。接続確認の結果は対応するリポジトリの下に表示され、ログにも記録されます。

ゲームの実行中は、プラグイン、リポジトリ、クライアント言語、クライアントのパス、互換性環境の変更を禁止します。ゲーム終了後は再び編集できます。複数の項目を入力するログイン認証情報は、引き続き「認証情報を保存」をクリックする必要があります。

ゲームリージョン間でプラグインを同期する前に、同期先の Dalamud API とプラグインのバージョンに互換性があることを確認してください。同期は選択した同期先のデータを上書きします。現時点では、繁体字中国語版のプラグイン DLL を他のゲームリージョンのバージョンと直接混用しないでください。

## 中国版のゲーム内データセンタートラベル

2.1.0 は **DCTravelerX**（[Dalamud-DailyRoutines/DCTraveler](https://github.com/Dalamud-DailyRoutines/DCTraveler)）向けに、Proton 環境でのランチャーとの通信をサポートします。中国版 Dalamud を有効にし、互換性のある DCTravelerX をインストールして本ランチャーからゲームを起動すると、プラグインのゲーム内データセンタートラベルを利用できます。ottercorp の DcTraveler や他のプラグインの互換性を保証するものではありません。

ゲーム起動後はフロントエンドを閉じても、バックエンドがゲームセッション、トラベル認証、Steam の状態を維持します。このバックエンドを手動で終了しないでください。ランチャーを再度開くとフロントエンドを利用できます。

トラベル認証の期限が切れると、保存済みのクイックログイン認証情報で復旧を試みます。QR 認証が必要な場合は、ランチャーを開くか、トラベルボタンの下の「ゲーム内 DC トラベルを再認証」から、**現在ゲームで使用中のアカウント**でスキャンしてください。ゲームを終了する必要はありません。復旧後はゲーム内で再操作してください。結果が不明なトラベル申請は自動再送しません。キャンセル、失敗、タイムアウト時はその認証を終了し、バックエンドの待機は最大 5 分です。

## ストレージのクリーンアップ

「このアプリについて」ページに 3 つの操作を追加しています。

| 操作 | 削除対象と保持する内容 |
| --- | --- |
| ダウンロードキャッシュを削除 | ランチャーが管理するパッチキャッシュやダウンロード・インストールの一時ファイルを削除します。インストール済みのゲーム、実行コンポーネント、プラグイン、バックアップを保持し、Dalamud 自身が管理する内容には介入しません |
| ログを削除 | ランチャーのログを削除します。現在のログはログモジュールと連携して空にし、他のプロセスが使用中のファイルや安全に処理できないファイルはスキップします。Dalamud のログは削除しません |
| 内蔵ブラウザーのキャッシュを削除 | 現在の Electron と Web 認証セッションの HTTP・コード・シェーダーキャッシュを削除し、Cookie と認証状態を保持します。旧版の独立した認証ブラウザーの残存ディレクトリは対象外です |

ゲーム実行中も利用できます。ダウンロード、インストール、ダウンロードキャッシュの削除は共通のプロセス間ロックを使用し、関連処理中はキャッシュを削除できません。操作や Web 認証中はブラウザーキャッシュを削除できません。結果には解放した容量とスキップ件数が表示されます。削除数が 0 の場合は、削除可能な対象がなかったことを示します。

起動時にはセッション記録と既知の一時ファイルも確認し、失効を確認できた記録を回収します。活動中のセッションや安全性を確認できないファイルは保持します。ディスク全体を走査するクリーナーではありません。

## 設定と認証情報

既定のデータディレクトリは次のとおりです。

```text
<launcher directory>/
├── ffxiv_cn/     # 中国版のデータ
├── ffxiv_tc/     # 繁体字中国語版のデータ
├── ffxiv/        # グローバル版のデータ
├── compatdata/  # pfx を含む既定の共通環境
└── logs/        # 診断ログ
```

Linux は AppImage、Windows は `FFXIVSuperLauncher.exe` と同じディレクトリにデータを保存します。Linux のアプリケーションメニュー登録は `XDG_DATA_HOME` に従います。Windows はデスクトップショートカットを作成し、スタートメニューには登録しません。アカウントと Dalamud のデータはゲームリージョンごとに分離します。

認証情報は各ゲームリージョンのディレクトリ内の `credentials.json` に平文でのみ保存します。パスワード、2FA シークレット、クイックログイン認証情報は暗号化しません。ランチャーが作成する認証情報ファイルは、現在のユーザーのみ読み書き可能です。アップロードや共有はしないでください。

2FA シークレットは 6 桁の認証コードとは異なります。シークレットは認証コードを生成するためのもので、認証コードはその回のログイン時にのみ入力します。シークレット欄に 6 桁の認証コードを入力しないでください。

報告時は、できるだけ次の情報を含めてください。

- ランチャーのバージョンと OS。Linux の場合はディストリビューション、デスクトップ環境、Proton のバージョンも記載してください。
