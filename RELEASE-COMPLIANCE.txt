二、随包二进制及素材

必须区别“用户从上游下载”和“我们已经装进发行包”两种情况。

- Tools/cn-launch-support：Soil 26-10-05-02 的固定注入器子集、依赖和 Windows
  .NET 10.0.1。并非没有随包分发 Dalamud 相关代码。需找到确切源仓库/提交、
  许可证、子模块及构建材料。NOTICE 链接到启动器仓库不能替代注入器来源。
- Tools/tc-entrypoint/Dalamud.Injector.dll：来自 yanmucorp/Dalamud 26-10-03-01，
  我们修改了 ArgFixer 调用。已有原始/修改后 SHA256 和 PatchInjector.cs。
  仅提供二进制补丁器不等于提供完整对应源码：仍需与原始二进制对应的源代码、
  适用许可证、构建及补丁步骤，显著标记改动者/项目、修改日期及改动内容。
- goatcorp/Dalamud 当前上游 LICENSE 为 AGPL v3；必须按实际打包分支及版本核对，
  不应以当前 master 的许可证直接代替历史版本证据。不能把全部 Dalamud 写成 GPL。
  GPL/AGPL 的聚合、链接及派生关系需按真实边界判断；单独进程并不是自动豁免。
- cn-launch-support 的缓存运行时打包分支没有复制 dotnet-LICENSE/THIRDPARTYNOTICES；
  0.11.5 实际目录缺少这两项专属文件。应使缓存与下载路径输出相同的法律材料。
- 主程序自包含 .NET、Skia/HarfBuzz 原生库、Avalonia 等：NuGet 依赖列表不能代替
  完整第三方声明。需覆盖运行时包、native assets 及内嵌子依赖，保留原版权文本。
- 当前通知生成器枚举全部 restore libraries，可能列入未分发的构建/其他平台包，
  同时遗漏实际分发的运行时和独立二进制。需改成发行目录清单与依赖图双向核对。
- Tools/webview：已附 Electron LICENSE 与 LICENSES.chromium.html，仍需核对固定
  Electron 版本及 FFmpeg 等组件的实际许可和对应源码义务，不能只写 Electron MIT。
- libsteam_api64.so：Global/UPSTREAM.md 记录从 xl 原样复制。Steamworks 托管包装器
  的 MIT 不等于 Valve 原生 SDK 库也是 MIT/GPL。需核实 SDK 来源和适用再分发条款。
- xdelta3：当前 vendored 源文件头及 LICENSE 均为 Apache-2.0，保留 Joshua MacDonald
  版权和完整许可证。已修正通知生成器误写 GPL 的说明；0.11.5 旧归档未被重写。
- logo.png、dalamud_icon.ico 等：需逐个核实作者、授权及商标使用边界；代码许可证
  不能在没有证据时自动覆盖所有游戏/项目品牌素材。无法确认时使用自有可授权素材。
- AppImage：构建后新增的 AppImage runtime、随带系统库及潜在更新器也必须纳入清单。

三、公开发布前必须完成的交付

[ ] 完成 xl_tw 文件级来源核查；仅对实际使用且无法追溯至获许可上游的独有实现解决授权。
[ ] 锁定 Soil/繁中注入器的准确源码版本、许可证及可获取的构建输入。
[ ] 核对 Steam API、图标以及原生/运行时依赖的再分发许可。
[ ] 保留上游版权、许可证和 NOTICE；不要全部换成我们自己的版权。
[ ] 增加来源/修改记录（项目、提交、路径、修改内容、相关日期），保留适用文件头。
[ ] 确定总体许可与 SPDX 标注，独立组件保留自身许可；不统一改成 MIT 或加入
    “禁止商用/禁止修改/禁止再分发”等与 GPL 权利相抵触的额外限制。
[ ] 每个二进制版本配套可取得的对应源码，包括构建/安装脚本、必要补丁和依赖来源。
    GitHub 自动生成的源码 zip 可能漏掉子模块/外部原生源码；下载 DLL 的脚本不能
    自行取代该 DLL 的对应源码。无需机械追求字节完全一致，但要提供修改和构建所需材料。
[ ] 对在线发布采用 GPLv3 6(d) 的等价源码获取方式：同一 Release 附完整源码或清楚
    标出可等价获取的对应源码位置，并维持可用。只放上游主页或最新主分支不够。
    不应无必要地采用另一种“至少三年书面要约”履约方式。
[ ] 根据 GPL 第 5(d) 条和所继承界面情况审查交互法律提示；“关于”提供方便查看的
    来源、版权、无担保、许可和对应源码入口是本项目拟采用的落实方式。
[ ] AUR 配方、AppImage 同版本使用一致的源码和通知；AUR 指向我们自己的发布地址，
    不是 AtmoOmen 上游地址。AUR 中仅有 PKGBUILD 不代替所分发二进制的源码义务。
[ ] 清理公开源码包：排除研究临时材料、用户校对工作表、本机路径及任何私人数据；
    不得遗漏受许可约束的必要源码。现有 git ls-files --others 打包方式需收紧范围。
[ ] 在干净环境验证源码可构建、法律文件确实进入两种包、来源链接/版本对应正确。
